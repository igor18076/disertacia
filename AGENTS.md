# Правила работы с CourseGen Research

Разработка ведётся на Windows, приёмка инфраструктуры — в Linux-контейнерах на Debian. Рабочий язык интерфейса и документации — русский. Исходное задание и границы первой поставки приведены в [ТЗ, § 23](docs/specification.md).

## Разработка

- Размещайте типизированный код в `src/coursegen`, изменения схемы PostgreSQL оформляйте ревизиями Alembic в `migrations/versions`.
- Меняйте конфигурацию через переменные окружения. Описывайте новые параметры в `.env.example`. Храните секреты на машине запуска. Включайте в диагностические сообщения только необходимые для разбора сбоя сведения.
- Фиксируйте версии образов и библиотек. Обновляйте `uv.lock` вместе с зависимостями. Сохраняйте файлы в UTF-8, скрипты для Linux — с окончаниями строк LF.
- Добавляйте тесты для новых модулей. Проверяйте реальные зависимости интеграционными тестами из профиля `test`. Для изолированных тестов допускаются явно заданные подмены.
- Описывайте решения, влияющие на воспроизводимость, в `docs/decisions/`. Фиксируйте измеренные результаты, ошибки и использованную конфигурацию.
- Согласовывайте изменение служб, пакетов, сетевых правил хоста и операции удаления данных или томов. Для работы приложения используйте выделенные Docker volumes или каталоги проекта.

## Последовательность работ

На этапах 0–1 проверьте окружение, запустите стек, примените миграции и пройдите интеграционные тесты по [README](README.md). При переходе к документам, поиску и генерации следуйте этапам 2–7 ТЗ. Загрузка больших моделей выполняется по явному запросу. Передача исходных документов внешним API требует отдельного разрешения.
