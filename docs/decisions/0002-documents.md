# ADR 0002. Версии источников и происхождение фрагментов

**Статус** — принято для этапа 2.

## Загрузка и хранение

API читает исходные байты из тела запроса `POST /api/v1/documents`. Имя файла передаётся параметром `filename`. Допустимы `.pdf`, `.txt` и `.md`; типы HTTP — `application/pdf`, `text/plain`, `text/markdown` соответственно или `application/octet-stream`. Лимит `DOCUMENT_MAX_BYTES` по умолчанию равен 16 МиБ и применяется в ходе чтения. Метаданные включают `source_type`, `publication_year`, `technology_version`, `currency`, `license_terms` и `language`. Значение актуальности по умолчанию — `requires_verification`, код неизвестного языка — `und`. Дату регистрации назначает PostgreSQL.

Оригинал, SHA-256 и параметры обработки хранятся в версии в PostgreSQL. Это позволяет сохранить источник и регистрацию одной транзакцией; резервная копия PostgreSQL содержит и оригиналы. Повтор той же загрузки с теми же метаданными возвращает существующую версию. Чтобы зарегистрировать новую редакцию, передайте `document_id` при загрузке. По умолчанию чтение возвращает последнюю редакцию; `?document_version=N` выбирает историческую. Оригинал доступен по `/{document_id}/original` относительно `/api/v1/documents`.

## Обработка

Worker выбирает очередную версию через PostgreSQL `FOR UPDATE SKIP LOCKED`. Страницы, фрагменты и итоговый статус публикуются одной транзакцией. При прерывании процесса версия снова доступна для выбора. `POST /{document_id}/reprocess` повторяет обработку оригинала с записанными параметрами. При прежнем содержимом и алгоритме идентификаторы фрагментов воспроизводятся. В API видны следующие состояния.

| Статус | Значение |
|---|---|
| `queued` | Версия зарегистрирована, результат ещё не опубликован |
| `ready` | Текст извлечён и разбит на фрагменты |
| `partial` | Есть текст и есть страницы PDF, требующие проверки/OCR |
| `needs_ocr` | В PDF отсутствует извлекаемый текст; оригинал доступен |
| `failed` | Причина записана в `error_code`, например `invalid_pdf`, `encrypted_pdf` или `invalid_utf8` |

PyMuPDF 1.28.2 извлекает текстовый слой и координаты блоков PDF на CPU. Для таблиц, формул и кода следует сверять порядок и расположение блоков с оригиналом; пустая страница PDF может оказаться сканом или действительно пустой страницей. Автоматический OCR в этот этап не входит. При использовании и распространении учитывайте условия AGPL или коммерческой лицензии PyMuPDF и права на сами учебные материалы. [Лицензирование PyMuPDF](https://pymupdf.readthedocs.io/en/latest/about.html#license-and-copyright)

TXT и Markdown читаются как UTF-8 с поддержкой BOM. Символ перевода страницы `U+000C` начинает новую логическую страницу. Без него весь текст — одна страница. Смещения задаются в символах Unicode в нормализованном тексте (NFC, окончания строк LF), начиная с нуля; конец диапазона исключён. Номера страниц начинаются с единицы.

## Разбиение и проверка

`CHUNK_STRATEGY=fixed` делит текст страницы на окна; `section` дополнительно ограничивает окна заголовками; `hierarchical` создаёт для длинного окна дочерние фрагменты с `parent_id`. Все стратегии сохраняют привязку к странице. `CHUNK_SIZE` задаёт размер окна в токенах (по умолчанию 800). Токенизация версии `pages-v1` считает последовательности букв, цифр и подчёркиваний, а также отдельные знаки пунктуации. `CHUNK_OVERLAP` — доля перекрытия (по умолчанию 0,12). Конфигурация сохраняется при регистрации новой версии. `embedding_model_version` на этапе документов имеет значение `null`.

`GET /{document_id}/pages/{number}` возвращает нормализованный текст, координаты PDF-блоков и признаки для ручной проверки. `GET /{document_id}/chunks` возвращает фрагменты в порядке следования с `limit` и `offset`. Проверка `/{document_id}/chunks/{chunk_id}/verify` заново извлекает текст из сохранённого оригинала и сравнивает диапазон и SHA-256. Она устанавливает происхождение цитаты; фактическая достоверность содержания исследуется на последующих этапах.
