# Требования РП и ФОС и граф дисциплины

## Извлечение и подтверждение

Worker обрабатывает версии `syllabus` (рабочая программа) и `assessment` (ФОС) после извлечения страниц. Миграция `0004_curriculum` включает в обработку и ранее загруженные версии. В ответе `GET /api/v1/documents/{id}?document_version=N` флаг `requirements_extracted` показывает завершение разбора. При частичном извлечении доступны требования из страниц с текстом.

Правила распознают русские подписи и заголовки разделов. Например, строка «Тема: Транзакции» даёт тип `topic` и значение «Транзакции». Отдельный заголовок «Компетенции» задаёт тип для следующих строк на той же странице. Извлекаются дисциплина, раздел, тема, компетенция, результат обучения, вид занятия, содержание, объём, практическая работа и критерий оценивания. Строка с неизвестной подписью вне распознанного раздела получает тип `other`. Переносы строк внутри требования и сложные таблицы требуют проверки оператором.

У всех кандидатов начальный статус `needs_review`. Нормализация удаляет подпись и сводит последовательности пробелов к одному. Точная цитата с координатами `[char_start, char_end)` относится к тексту конкретной страницы и версии. UUID учитывает документ, версию, страницу, позицию и цитату. При повторном извлечении совпавший кандидат сохраняет правку и статус.

1. Загрузите документ через `POST /api/v1/documents?filename=rp.txt&source_type=syllabus` с телом файла. Для ФОС передайте `source_type=assessment`.
2. Получите `GET /api/v1/requirements?document_id=UUID&document_version=1&status=needs_review`. Доступны фильтр `kind` и постраничный вывод через `limit` и `offset`.
3. Сверьте цитату через `GET /api/v1/documents/{id}/pages/{page}?document_version=N`. Подтвердите её через `PATCH /api/v1/requirements/{requirement_id}` с телом `{"expected_revision":1,"status":"approved"}`. В том же запросе можно исправить `kind` и нормализованный `text`. Для отклонения передайте статус `rejected`. Конфликт параллельных правок возвращает HTTP 409.

## Версии графа

`POST /api/v1/graph/from-requirements` принимает `{"discipline":"Базы данных","requirement_ids":["UUID"]}`. Выбираются утверждённые требования о дисциплине, разделе, теме, результате обучения или компетенции. Ответ содержит `graph_id`, `version` и снимок. Начальный граф связывает узлы с источниками через `supported_by`. На узле зафиксирована ревизия утверждения.

Для редактирования получите `GET /api/v1/graph?graph_id=UUID&version=1` и отправьте обновлённый снимок через `PUT /api/v1/graph/{graph_id}` с полями `base_version` и `graph`. Для создания вручную используйте новый UUID и `base_version=0`. PostgreSQL сохраняет каждую версию отдельной записью. Одновременная публикация на основе одной версии возвращает HTTP 409 одному из редакторов. Старые снимки сохраняют состояние на момент публикации. Изменение требований учитывается при публикации следующего снимка.

Узлам доступны типы `topic`, `concept`, `outcome`, `competency`, `source` и `chunk`. Для каждой связи указываются направление, тип, происхождение и основание `basis`. Для происхождения `document` обязательна ссылка `evidence_chunk_id`. При записи проверяются ссылки, версии источников и ревизии утверждённых требований. Происхождение `llm` сохраняет предложение в снимке. Для включения предложения в действующие пререквизиты эксперт публикует новую версию с происхождением `expert` и описанием основания.

## Поиск и пробелы

NetworkX 3.5 строит ориентированный граф действующих пререквизитов. Связь `A prerequisite_of B` означает, что A изучается до B. При попытке опубликовать цикл API возвращает HTTP 422 и путь цикла. `GET /api/v1/concepts` перечисляет понятия выбранного графа. `GET /api/v1/graph/prerequisites?graph_id=UUID&version=2&concept_id=B&known=A` возвращает транзитивные пререквизиты в порядке изучения и те из них, которые отсутствуют в переданном наборе освоенных понятий. Параметр `known` можно повторять.

В запросе `POST /api/v1/search` режим `hybrid_graph` требует поля `graph`. Пример тела запроса:

```json
{
  "query": "отмена операции",
  "mode": "hybrid_graph",
  "graph": {"graph_id": "00000000-0000-0000-0000-000000000001", "version": 2, "concept_id": "rollback", "sources_only": true},
  "top_k": 3
}
```

Подставьте идентификаторы своего графа и понятия. К исходному запросу добавляются до 16 уникальных названий цели и пререквизитов в обратном топологическом порядке. BM25 и dense получают расширенный текст, затем Qdrant объединяет результаты через RRF. В `graph.terms` каждого результата видны добавленные названия. При `sources_only=true` обе поисковые ветви ограничены версиями документов и фрагментами, связанными с целью или её пререквизитами через действующие связи `supported_by`. Это ограничение пересекается с исходными фильтрами пользователя. Для повторения эксперимента фиксируйте версию графа, версии корпуса и параметры поиска.
