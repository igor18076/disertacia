# Поиск и публикация индекса

## Представления текста

Коллекция `coursegen_chunks_v1` хранит одну точку на каждый фрагмент с ролью `leaf`. UUID точки совпадает с `chunk_id`. В PostgreSQL остаются оригинал, цитируемый текст, страницы и символьные координаты. В Qdrant записываются именованные векторы, идентификаторы, поколение индекса, хеш текста и поля фильтрации.

| Параметр | Значение |
|---|---|
| Dense-кодировщик | `TrendHD/rubert-tiny2-int8`, ревизия `0580fbdeab7db787152458828ac57ac7f157ab90`, исходная модель `cointegrated/rubert-tiny2`, лицензия MIT |
| Исполнение | ONNX Runtime 1.26.0, CPU, один поток на вычисление, INT8 |
| Вход | Одинаковая обработка запроса и фрагмента. Удаляются крайние пробелы, WordPiece добавляет служебные токены, учитываются первые 512 токенов вместе со служебными |
| Вектор `dense` | Последний скрытый слой для токена CLS, L2-нормализация, 312 координат, косинусная мера |
| Вектор `bm25` | Встроенный в Qdrant 1.20.2 кодировщик `qdrant/bm25`, параметр языка `russian`, модификатор IDF |
| Ранжирование `hybrid` | Qdrant RRF, `k=60`. По умолчанию по 30 кандидатов от каждого метода. Поля запроса `dense_candidates`, `bm25_candidates` и `top_k` задаются независимо |

Архив модели включает ONNX и токенизатор. Скрипт подготовки и приложение сверяют SHA-256 обоих файлов. API и worker загружают их с диска при первом вычислении. Выбор компактного кодировщика проверен на русских запросах и двух запросах с английскими техническими терминами. [Исходная модель](https://huggingface.co/cointegrated/rubert-tiny2) · [Закреплённые веса ONNX](https://huggingface.co/TrendHD/rubert-tiny2-int8/tree/0580fbdeab7db787152458828ac57ac7f157ab90)

Схема коллекции включает имена векторов, размерность, меру, модификатор и метаданные с версией кодировщика. Несовпадение останавливает операцию с кодом `collection_schema_mismatch`. При смене модели потребуется отдельная коллекция и переиндексация. BM25 рассчитывается сервером Qdrant в сети приложения. Запрос гибридного поиска использует два предварительных поиска и RRF. В ответе есть итоговая оценка и оценки тех ветвей, в списки кандидатов которых попал фрагмент. [BM25 в Qdrant](https://qdrant.tech/documentation/inference/inference-bm25/) · [Гибридный поиск и RRF](https://qdrant.tech/documentation/search/hybrid-queries/)

## Версии, фильтры и восстановление

`POST /api/v1/documents/{id}/index` принимает версию в состоянии `ready` или `partial`. API сохраняет задание в PostgreSQL и возвращает HTTP 202. По умолчанию выбирается последняя загруженная версия. Предыдущая доступна через явный `document_version`. Это правило действует и в поиске, в том числе пока новая версия ещё обрабатывается.

Worker блокирует задание, удаляет прежние точки этой версии, записывает фрагменты пакетами и сверяет UUID, хеши и поколение с PostgreSQL. Только после сверки статус становится `indexed` и поколение попадает в выдачу. При обрыве процесса транзакция освобождает задание для следующего worker. Зафиксированную ошибку можно посмотреть через `GET /api/v1/documents/{id}/index` и повторить операцию тем же POST. Повторное извлечение страниц также ставит ранее опубликованный индекс в очередь.

Параметр `verify=true` возвращает число ожидаемых и фактических точек и счётчики пропусков, лишних точек и расхождений. `DELETE /api/v1/documents/{id}/index?document_version=N` снимает версию с поиска и ставит удаление её точек в очередь. После завершения GET возвращает `absent`. Источник остаётся доступен через API документов.

`POST /api/v1/search` принимает режим, запрос и фильтры. `allowed_document_ids` задаёт корпус, пустой список даёт пустую выдачу. `source_type`, `currency`, `document_version` и `topic` действуют совместно. Тема совпадает с меткой `topic`, переданной при загрузке, либо с одним из заголовков пути раздела. В ответе для каждого результата есть использованные фильтры, ранг, исходная цитата, файл, версия и страницы.

## Контрольный набор

Набор `search-v1` содержит шесть синтетических источников и восемь запросов с одним размеченным источником для каждого. При стандартном разбиении каждый источник даёт один фрагмент. Скрипт ограничивает поиск этими документами, запрашивает по десять кандидатов от каждой ветви и сохраняет ранг размеченного источника среди первых трёх результатов. При нескольких фрагментах одного документа учитывается первое вхождение источника. Для сравнения измеряются Recall@3, Precision@3, MRR@3 и nDCG@3 по бинарной разметке. После одного прогрева на режим измеряется время HTTP-запроса. IDF зависит от всей коллекции, поэтому для сопоставимых экспериментов следует фиксировать её состав.
