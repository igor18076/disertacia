## Первый прогон на Debian

20 ноября 2026 года в 05:21 UTC для коммита `343bd4b` с локальными изменениями прошли шаги `env` и `preflight` (Docker Engine 29.10.0, Compose 5.8.0). На шаге `stack` во время `uv sync` сборщик исчерпал попытки разрешить имя `files.pythonhosted.org` при загрузке `psycopg==3.3.9`. Отчёт завершился с `FAIL stack (1)`. Проверки миграции, готовности API и интеграционные тесты в этом прогоне не выполнялись. [Диагностика сборки](deployment.md#ошибка-dns-при-загрузке-пакетов-python)

21 ноября 2026 года в 01:34 UTC для коммита `aacdae7` с локальными изменениями снова прошли `env` и `preflight`. Compose принял адреса PyPI, полученные на хосте. При попытке скачать `numpy==2.5.5` команда `uv sync` исчерпала попытки установить TCP-соединение с `files.pythonhosted.org`. В этом прогоне также получен `FAIL stack (1)`; проверка сервисов ожидает успешной сборки.

Для следующего запуска подготовлен архив из 42 wheels для Linux amd64, SHA-256 `fdf9a4ff39743de816049193fe17c1bfc51e5c45ede0f899068a11bcada6b19f`. В изолированном Linux-окружении WSL из закреплённых образов зависимости установились без доступа к PyPI. Alembic применил ревизию `0001_infrastructure` к PostgreSQL 17.12. Запущенный API вернул HTTP 200 от `/ready` с обеими проверками `ok`, включая Qdrant 1.20.2. Прошли 9 модульных и 4 интеграционных теста.

Для Compose 5.8.0 и Buildx 0.39.0 проверена итоговая конфигурация всех трёх целей сборки. Критерием приёмки на целевом сервере остаётся `result=PASS` после запуска [с локальными пакетами Python](deployment.md#сборка-с-локальными-пакетами-python).

## Проверка этапа 3 перед развёртыванием

25 ноября 2026 года на Linux-стенде WSL2 с CPU Intel Core i7-7700K применена миграция с `0002_documents` до `0003_search`. Использованы файловые системы закреплённых образов PostgreSQL 17.12, Qdrant 1.20.2 и Python 3.12.14. Зависимости установлены из архива при отключённой внешней сети. Alembic подтвердил соответствие схемы, API вернул HTTP 200 от `/ready`. Прошли 39 тестов за 10,87 с. Повторный запуск четырёх интеграционных тестов поиска на той же базе прошёл за 7,35 с. Проверены пропажа точки, диагностика, восстановление и удаление версии из поиска.

Для замера отдельная коллекция содержала только шесть документов `search-v1`. Стратегия разбиения `section`, размер 800, перекрытие 0,12. У каждого источника один фрагмент. На восьми запросах с одним размеченным источником получены следующие результаты.

| Поиск | Recall@3 | Precision@3 | MRR@3 | nDCG@3 | p50, мс | p95, мс |
|---|---:|---:|---:|---:|---:|---:|
| BM25 | 0,875 | 0,292 | 0,875 | 0,875 | 14,36 | 16,10 |
| Dense | 1,000 | 0,333 | 0,938 | 0,954 | 14,34 | 16,44 |
| Hybrid RRF | 1,000 | 0,333 | 0,854 | 0,891 | 15,70 | 17,93 |

По запросу «Как вернуть файлы после отказа накопителя?» BM25 пропустил источник о резервных копиях, dense поставил его первым, hybrid третьим. При восьми замерах на режим p95 по методу ближайшего ранга соответствует самому медленному запросу. Результаты относятся к синтетическому набору и этому стенду. [Методика](decisions/0003-search.md)

Архив `coursegen-wheels-cp312-linux-amd64.tar.gz` содержит 52 пакета, SHA-256 `eb805a1be1f1bed4da831ca589ffc4b1feac696c4b63671e0e401ec05fe547cb`. SHA-256 архива `coursegen-search-model.tar.gz` равен `e18571dae63a4d78b06d1ae92373cde47e567333c6b41c76664d963fbec5065b`. Compose 5.8.0 принял оба варианта конфигурации. Во всех четырёх автономных целях сборки задано `network: none`, API, worker и тесты подключают модель только для чтения.
