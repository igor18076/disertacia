# Архитектура CourseGen Research

Код хранится в Git. На Debian один checkout, файл `.env` и Docker Compose задают конкретную установку. Образы PostgreSQL и Qdrant хранят данные в отдельных именованных томах, поэтому рабочую копию можно обновлять независимо от данных.

```text
Windows ── Git ──► рабочая копия на Debian
Windows ── SSH-туннель ──► 127.0.0.1:8000 ──► FastAPI
                                                ├── PostgreSQL
                                                └── Qdrant
                                  Alembic ─────────► PostgreSQL
```

## Структура репозитория

| Расположение | Ответственность |
|---|---|
| `compose.yaml`, `docker/` | Сервисы, сборка, тома и сетевые границы установки |
| `.env.example`, `pyproject.toml`, `uv.lock` | Параметры развёртывания и версии зависимостей |
| `src/coursegen/api/` | HTTP-маршруты, OpenAPI и жизненный цикл клиентов |
| `src/coursegen/core/` | Типизированные настройки |
| `src/coursegen/documents/`, `src/coursegen/chunking/` | Очередь версий, worker, извлечение текста и координат, стратегии разбиения |
| `src/coursegen/db/`, `migrations/`, `alembic.ini` | Подключение к PostgreSQL и версия схемы |
| `tests/unit/`, `tests/integration/` | Контракт API и проверка работающих сервисов |
| `scripts/` | Операционные проверки |
| `docs/`, `docs/decisions/` | ТЗ, развёртывание, границы этапов и архитектурные решения |

## План по этапам

| Этап | Модули и результат |
|---|---|
| 0. Окружение | Проверить платформу разработки, на целевом сервере выполнить `scripts/preflight.sh`. |
| 1. Инфраструктура | Поднять PostgreSQL и Qdrant, применить миграцию, получить HTTP 200 от `/ready` и пройти тестовый профиль. |
| 2. Документы | `documents/`, `chunking/` и тестовый корпус в `datasets/synthetic/`. Проверить воспроизводимость фрагментов и ссылок на страницы. |
| 3. Поиск | `retrieval/` содержит CPU-кодировщик, обработчик индекса и поиск. `scripts/benchmark_search.py` сравнивает три режима на размеченных запросах. |
| 4. РП, ФОС и граф | `requirements/`, `knowledge_graph/`. Привязать требования к источникам и подтверждениям, версионировать граф. |
| 5. Генерация | `planning/`, `providers/`, `generation/`. Ввести критерий достаточности, worker и дополнительный профиль локальной LLM. |
| 6. Верификация | `verification/`, `tests/e2e/`. Проверять утверждения, ссылки и покрытие требований на синтетическом корпусе. |
| 7. Эксперименты | `evaluation/`, `experiments/`. Сохранять параметры прогонов и рассчитывать метрики по версионированной разметке. |

Оператор подтвердил прохождение тестов этапа 3 на Debian. На этапе 4 таблицы требований и снимков графа добавляет миграция `0004_curriculum`. Строки 5–7 описывают последующие работы. [Решение по этапу 4](decisions/0004-curriculum.md) · [Техническое задание](specification.md)
