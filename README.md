# CourseGen Research

Исследовательский проект по генерации учебных материалов с проверкой источников. Первая поставка по ТЗ охватывает этапы 0 и 1 — подготовку окружения и контейнерную инфраструктуру. FastAPI проверяет доступ к схеме PostgreSQL и получает список коллекций Qdrant. Для запуска достаточно CPU.

## Windows → Git

Редактируйте проект в этой папке. Для переноса на Debian в Git должны попасть исходники, `uv.lock`, миграции, Dockerfile, `compose.yaml` и `.env.example`. Реальные настройки из `.env`, базы, документы и модели исключены из Git. Правила в `.gitattributes` сохраняют LF для Linux-скриптов.

Для первой публикации создайте пустой удалённый репозиторий. В PowerShell из корня проекта отправьте ветку `main`, подставив свой Git URL. Если `origin` уже настроен, пропустите строку `git remote add origin`.

```powershell
git remote add origin '<URL вашего репозитория>'
git push -u origin main
```

## Первый запуск на Debian

Требуются Git, Docker Engine с поддержкой Linux-контейнеров, Buildx и плагин Compose с поддержкой `up --wait`. Выберите каталог, в который у вашего пользователя есть право записи. В примере администратор выделил `/opt/coursegen`. Обычная сборка получает образы из реестров, а пакеты Python из PyPI. Для сервера с ограниченным исходящим HTTPS пакеты можно подготовить на Windows. [Сборка с локальными пакетами](docs/deployment.md#сборка-с-локальными-пакетами-python)

```sh
git clone '<URL вашего репозитория>' /opt/coursegen
cd /opt/coursegen
sh scripts/accept-infra.sh
```

При первом запуске скрипт создаёт приватный `.env` со случайным паролем PostgreSQL. При повторном запуске он использует имеющийся файл. Если вы ранее скопировали шаблон, заполните пустой `POSTGRES_PASSWORD` в редакторе до запуска. При переносе существующей базы восстановите соответствующий ей `.env` из своего защищённого хранилища.

Скрипт проверяет окружение, собирает и запускает контейнеры, проверяет завершение Alembic и ответ `/ready`, затем запускает pytest с настоящими PostgreSQL и Qdrant. Результат сохраняется в `results/infrastructure/`. Строка `result=PASS` означает, что все шаги прошли. При ошибке скрипт возвращает ненулевой код и указывает шаг в отчёте. Для диагностики используйте `docker compose ps -a` и `docker compose logs --tail 100 migrate api postgres qdrant`. [Проверка сервера, установка Docker и резервное копирование](docs/deployment.md)

Если порт 8000 занят, измените `API_PORT` в созданном `.env` и повторите запуск. Параметры `*_CPUS` и `*_MEMORY` задают пределы ресурсов контейнеров. Для настройки **до первого запуска** выполните `sh scripts/init-env.sh`, отредактируйте `.env`, затем запустите приёмку. При смене пароля существующей установки обновите также пароль роли в БД.

## Доступ с Windows

Оставьте SSH-туннель открытым в отдельном окне PowerShell. Подставьте свой логин и адрес Debian. Если на сервере изменён `API_PORT`, замените последнее число 8000 в команде `-L`.

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18000:127.0.0.1:8000 user@server
```

В другом окне PowerShell запросите состояние API и его зависимостей.

```powershell
Invoke-RestMethod http://127.0.0.1:18000/health
Invoke-RestMethod http://127.0.0.1:18000/ready | ConvertTo-Json
```

| Маршрут | Ожидаемый результат |
|---|---|
| `GET /health` | HTTP 200, `{"status":"ok"}`, если API отвечает |
| `GET /ready` | HTTP 200 при доступности обоих хранилищ, HTTP 503 с полем `checks` при сбое |
| `GET /docs`, `GET /openapi.json` | Swagger UI и машиночитаемая схема API |

## Обновление и остановка

Для обновления запушьте изменения с Windows. На Debian из рабочей копии выполните следующие команды.

```sh
git pull --ff-only
sh scripts/accept-infra.sh
```

Для остановки выполните `docker compose down`. Именованные тома с данными сохраняются для следующего запуска.
